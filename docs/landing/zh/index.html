让你的编码智能体去问图，
而不是翻文件。

Dr Strange 把一个代码仓库消化为符号与已解析关系构成的图，并回答智能体在动手 改动之前会问的那些问题——谁调用了它、改动会波及到哪里、一个符号如何到达另一 个、哪些 HTTP 路由彼此对应——每个问题一次往返，全程没有模型参与。

消化本仓库——9.7 万行、13 个解析插件——得到 10,237 个符号与 44,927 条 已解析的边。没有任何模型调用。

1/61 的 token

回答「谁调用了它、改动会波及到哪里」的中位开销是 925 个 token；grep 名字 再把匹配到的文件读完则是 53,720 个。

两个数字都是实测而非估算，且都可复现——方法、脚本，以及为使第二个数字站得住脚 而设的排除项，都记在 BENCHMARKS.md 里。

安装

一行命令，无需工具链。安装脚本会在解包前校验发行归档的 SHA-256。

# Linux 与 macOS
$ curl -fsSL https://raw.githubusercontent.com/wangyingsm/dr-strange/master/scripts/install.sh | sh

# Windows（PowerShell）
PS> irm https://raw.githubusercontent.com/wangyingsm/dr-strange/master/scripts/install.ps1 | iex

# 然后，在你希望智能体理解的那个仓库里：
$ drsg plugin install   # 挑选解析器；0 表示全选
$ drsg init             # 消化、起服务、写入 MCP 配置

从国内访问 GitHub 较慢时，--mirror <base-url> 可让镜像接手； 无论由哪一方应答，校验和都会被核对。发行归档同时附带 已签名的构建来源证明。

一条命令，配好你正在用的那个智能体

drsg init 消化当前工作区，起一个把每次提交折叠进图的 watcher， 并为本仓库或本机留有痕迹的那些智能体写好 MCP 配置。

十三个动词，每个一次往返

这十三个既是 drsg serve 上的 MCP 工具，也都是命令行子命令。

context关于一个符号的一切——首选动词
impact改动会波及到哪里，按距离分组
trace两个符号之间图中记录的最短调用路径
wire谁在提供某个 HTTP 路径，谁在请求它
grep在被监视的树上检索，每个命中标出所在符号
search「我不知道名字」：语义 top-k
snippet一个符号的源码，或文件的某个行区间
describe一个符号的属性，只看节点
fathom一个符号身处怎样的区域，以及其中的枢纽
history代码背后的那个仓库
recall同一份代码在任意提交时的样子
deployed某个运行中的东西是哪次提交构建的
affected一次改动波及的测试，而不是整个套件

这些回答凭什么可信

  • 没有模型解析你的代码。沙箱化的 wasm 解析器插件——官方目录共十三个， 其中八个是语言——产出这些事实。LLM 是可选的，且从不参与解析。
  • 歧义的名字从不猜测。回答是一份候选清单，由调用方挑选。
  • 调用清单是一个明示的下界。解析器无法解析的部分会连同原因保留，并且 回答会说明这一点。错误的边比缺失的边更糟。
  • 图就是已提交的代码。serve watch 逐个提交地跟进仓库， 每个回答开头都会说明它读的是哪个提交。
