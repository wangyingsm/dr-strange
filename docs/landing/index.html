Your coding agent asks the graph,
not the files.

Dr Strange digests a repository into a graph of symbols and resolved relationships, then answers the questions an agent asks before it changes anything — who calls this, what a change would reach, how one symbol reaches another, which HTTP routes meet — one round trip each, with no model in the loop.

Install

One line, no toolchain. The installer verifies the release archive's SHA-256 before unpacking it.

# Linux and macOS
$ curl -fsSL https://raw.githubusercontent.com/wangyingsm/dr-strange/master/scripts/install.sh | sh

# Windows (PowerShell)
PS> irm https://raw.githubusercontent.com/wangyingsm/dr-strange/master/scripts/install.ps1 | iex

# Then, in the repository you want your agent to understand:
$ drsg plugin install   # choose parsers; 0 = all
$ drsg init             # digest, serve, write the MCP config

On a slow link to GitHub, --mirror <base-url> lets a mirror take over; the checksum is verified whichever source answers. Release archives also carry signed build provenance.

One command configures the agent you already use

drsg init digests the working tree, spawns a watcher that folds every commit into the graph, and writes the MCP configuration for whichever of these your repository or your machine shows a sign of.

Thirteen verbs, one round trip each

All thirteen are MCP tools on drsg serve, and all thirteen are CLI subcommands.

contexteverything about one symbol — the primary verb
impactwhat a change would reach, by distance
tracethe shortest recorded call path between two
wirewhat serves an HTTP path, and what asks for it
greptext over the watched tree; each hit names its symbol
search“I don't know the name”: semantic top-k
snippeta symbol's source, or a range of a file
describeone symbol's properties, node only
fathomthe region a symbol sits in, and its hubs
historythe repository behind the code
recallthe same code as it was, at any commit
deployedthe commit a running thing was built from
affectedthe tests a change reaches, not the whole suite

What makes the answers worth trusting

  • No model parses your code. Sandboxed wasm parser plugins — thirteen in the official catalog, eight of them languages — produce the facts. An LLM is optional and never in the parsing path.
  • An ambiguous name is never guessed at. The reply is a list of candidates to pick from.
  • A call listing is a stated lower bound. What the parser could not resolve is kept with its reason, and the answer says so. A wrong edge is worse than a missing one.
  • The graph is the code as committed. serve watch follows the repository commit by commit, and every answer opens by naming the commit it read.
