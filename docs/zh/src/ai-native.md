# AI 原生

本章介绍那些将 Dr Strange 界定为一个*为* AI 工作负载而设计的数据库的能力：原生的
向量与关键词索引、融合式混合检索、自然语言查询，以及由 LLM 驱动的文档导入。时间
旅行与变更流——对智能体工作负载同样关键——分别在[第 4 章](./query-language.md)介绍，
并在本章末尾引用。

## 向量属性与 HNSW 索引

一个取值为向量的属性，就是一个嵌入；它被原生建立索引，从而使相似度检索在查询引擎
内部执行，而非在外部服务中进行。

索引以一个距离度量声明在某个 `(标签, 属性)` 对上。引擎会为携带该向量属性的、具有
该标签的每个节点构建一个 [HNSW](https://arxiv.org/abs/1603.09320) 索引，并在写入
提交时保持其一致：

```console
$ drsg --db graph.drsg index ensure Doc embedding --plane social
$ drsg --db graph.drsg index ensure Doc embedding --plane social --metric dot
```

度量可取 `cosine`（默认）、`dot` 或 `l2`。声明是幂等的；以不同度量重复声明同一个对
是错误。构建好的索引持久化在数据库旁的 `.hnsw` 伴生文件中，并在打开时重新加载。

查询通过 `SEARCH … NEAR … TOPK` 形式使用索引；当未声明索引时，引擎回退到精确的暴力
扫描——这也是用来校验索引的基准（oracle）。

## 关键词（BM25）索引

词面相关性是对语义相似度的补充。关键词索引以一个字符串属性声明在某个 `(标签, 属性)`
对上，并按 Okapi BM25 对文档排序：

```console
$ drsg --db graph.drsg index keyword Doc body --plane social --lang english
```

每个索引都带有一个分析器**语言**（`english`/`en`、`french`/`fr`，以及其它 Snowball
支持的语言），它决定所用的词干还原器与停用词集合；值在建立索引前会被小写化、分词、
过滤停用词并做词干还原。构建好的索引持久化在 `.bm25` 伴生文件中。

## 混合检索

有效的检索很少只依赖单一信号。混合检索最多组合三路信号，并返回一个排序结果：

- **向量** —— 基于某个已声明向量属性的嵌入相似度；
- **关键词** —— 基于某个已声明关键词属性的 BM25 相关性；
- **图** —— 到最强的向量/关键词命中点的邻近度，向外扩展并随跳数衰减。

```console
$ drsg --db graph.drsg hybrid "how does time-travel work" \
    --plane social --label Doc \
    --vector embedding --keyword body \
    --graph-hops 1 --k 10 --embed openai
```

每一路信号贡献一个候选集；各分数在其所属信号内做 min-max 归一化，再以加权和合并
（默认权重：向量 1、关键词 1、图 0.5），最终返回前 `k` 个。启用某一路信号，只需指名
其属性；图信号由 `--graph-hops` 启用。关键词信号需要一个标签，因为 BM25 索引是按
标签划定范围的。

## 自然语言查询

`plane.ask` 将一个自然语言问题编译为查询、执行它，并返回连通的子图。模型以该平面的
软 schema（其标签、属性类型与边类型连接关系）为依据，被要求产出一个可序列化的逻辑
计划。

```console
$ drsg --db graph.drsg ask "which companies does Ada work for?" \
    --plane social --chat deepseek --embed qwen
```

其过程是一个智能体循环，而非一次单独的调用：

- **分解。** 复合问题被拆分为若干独立的子问题，每个子问题对应一个计划。
- **有据的工具。** 模型可以调用基于嵌入的工具——`find_edge` 与 `find_entity`——
  按相似度检索该平面自身的边描述与实体，从而选出真实存在的边类型与种子节点，而非
  凭空猜测。
- **修复。** 无法解析或执行的计划会连同错误一并返回给模型，进行有界次数的修复尝试。

查询是**只读的**：逻辑计划没有写算子，因此 `ask` 无法改动图。`--dry-run` 只返回生成
的计划而不执行；结果中还携带一份工具调用与修复的轨迹（trace），以供检视。

## 文档导入（AIgest）

导入将非结构化文本转化为图结构。一篇文档被分块；LLM 从每个块中抽取实体与带类型的
关系；抽取结果随后被清理（见下）；实体被嵌入；每个实体在找到既有节点时链接到它
（以避免重复），否则新建；最终结果经由批量路径写入。

```console
# 仅预览（默认行为）：报告将要写入的实体与关系。
$ drsg --db graph.drsg digest notes.md --plane social --chat openai --embed openai

# 提交此次抽取。
$ drsg --db graph.drsg digest notes.md --plane social --apply
```

### 抽取精度

各个块是彼此独立抽取的，因而没有任何机制促使它们收敛：同一类事物获得多个标签，同一
种关系获得多个边类型，同一个实体获得多个名字；又因为块是按位置合并的，一个实体的
属性由**最先**提到它的那个块所固定，此后每一次更完整、更准确的提及都被丢弃。

抽取之后有三道清理流程。它们并不逐项配置——由一个选项决定运行其中的前几道，因为它们
构成一条成本递增的序列：

| `--mode` | 流程 | 所换取的 |
|---|---|---|
| `coarse` | 词表归一 | 一类事物一个标签，一种关系一个边类型 |
| `fine`（默认） | \+ 身份消解 | 一个实体一个节点 |
| `super` | \+ 逐实体精修 | 属性取自全篇文档 |

- **词表归一**将标签集合与边类型集合规范化——处理的是*集合*，因此无论文档多长，其模型
  调用次数都是常数。仅在大小写或分隔符上有差异的名字无需模型即可归并。
- **身份消解**合并指称同一事物的实体，将边的端点改写到留存者上，并折叠由此产生的重复
  边与自环。它还会以精确匹配核对每个 key 是否已存在于平面中，因此重新导入同一篇文档
  是链接而非再造。
- **逐实体精修**将每个实体与提及它的*所有*段落及其关系一并重读，在完整图景之下重新
  询问它的属性。若某实体除产生它的块之外无新内容可读，则直接跳过、不产生调用。这是
  修复「首块获胜」的一道流程——代价也相应高昂：**输入 token 约为 `fine` 的 15 倍**，
  因为每个符合条件的实体都要带着自己的段落发起一次独立请求。

凡是名字被规范化或被合并之处，文档原本使用的写法都会以 `_label_as_written` /
`_type_as_written` / `_key_as_written` 保留在旁。下划线前缀的属性属于溯源信息：它们
不出现在模型所读的 schema 摘要中，因此别名不为读路径带来任何代价，同时使文档自身的
措辞始终可追回。

各个入口都可导入文档：命令行、MCP 的 `digest` 工具，以及仪表盘的 **AIgest** 页。
Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV 与 PDF 会先转换为 Markdown，并在
写入前预览拟议的实体与关系。提交预览时不再产生任何额外的模型调用。

### 从 URL 读取

文档可以用地址指定，而不必上传。服务端抓取该页面，将其转换为 Markdown，在预算范围内
沿其链接继续抓取，并组装成一篇文档——此后它与粘贴进来的文档走完全相同的导入流程。

```console
$ drsg --db graph.drsg digest https://example.com/paper \
    --plane papers --topic "attention mechanism" --pages 6 --apply
```

一个页面的出链是一份经过挑选的参考书目：作者已经替我们判断过什么与之相关。困难在于
这些链接同时也指向 cookie 政策与导航栏。因此**相关性要判定两次**，而跳数什么也不
决定——深度衡量的是爬取走了多远，而非某个页面是否真的与主题有关。

- *抓取之前*，每个链接只依据手头已有的信息评分：锚文本、`title` 属性，以及 URL 路径
  中的词。不联网，不调用模型。只有得分最高的候选才值得一次请求。
- *抓取之后*，再依据页面的实际正文重新评分；名不副实者被丢弃，代价恰好是一次请求。

两者使用与 BM25 索引相同的分析器，因此链接中的 “transformers” 能够匹配目标词
“Transformer”。`--topic` 会锐化目标；若留空，则以页面自身的主题作为爬取的目标。跳数
衰减仅作为倾向根页面的平局裁决而保留。

每个页面的地址都记录在文本之中，且页面边界必定开启一个新的块，因此任何一个块都不会
混入两篇文档：

```markdown
<!-- drsg:source https://example.com/paper -->

# Attention Is All You Need
…
```

各项预算——页数、深度、单次响应大小、总下载量、耗时——才是真正的控制手段，且**凡被
预算丢弃者必被报告**。命令行会打印保留了什么、丢弃了什么；仪表盘则以带勾选框的列表
呈现同样的内容。

URL 抓取默认启用。默认*不*包含的，是触及私有网络的能力：服务端拒绝连接回环地址、
私有地址、链路本地地址（`169.254.0.0/16`，云实例元数据服务所在之处）以及其它不可路由
的地址；检查针对的是**解析后的地址**而非主机名，并在每一次重定向跳转时重新检查。若
运维者确需读取内网资源，可精确地重新放行该网段，且这是唯一的例外，见
[第 2 章](./getting-started.md#配置文件)。`robots.txt` 会被遵守，爬虫会表明自己的
身份，对同一主机的请求之间也会留出间隔。

已知限制：正文由浏览器中的 JavaScript 组装而成的页面，抓取到的只是一具没有正文的
外壳。本项目不包含无头渲染器。

### 读取代码库

将 `digest` 指向一个目录，它会遍历整棵树，并把每个文件交给能够处理它的处理器。源码
文件是被**解析**的，而不是被阅读的：得到的是一个编译器级别的解析器所确知的事实，而
非模型对文本的理解。

解析器是**插件**——安装一次、随处可用的沙箱化 WebAssembly 组件：

```console
$ drsg plugin install https://github.com/…/releases/download/rust-v2/rust.wasm
installed rust@2  sha256:e3a586a150d0
  handles: .rs
```

制品的 SHA-256 在安装时被锁定，并在每次加载时重新校验，因此磁盘上被改动过的文件会
被拒绝，而不是被悄悄运行。在沙箱内，插件能触及的只有三件事——列出文件、读取文件、
询问这棵树的名字——全部以被导入的目录为根，并按解析后的路径检查。没有文件系统，没
有网络，没有环境变量，时钟被冻结，指令数与内存都有硬性预算（`drsg.toml` 的
`[plugins]` 节）。一个哪怕只是导入了文件系统接口的组件，都会在安装时被指名拒绝。

```console
$ drsg --db graph.drsg digest ./crates/dr-strange-core/src --plane code --apply
preprocessed by rust@2 (5528 facts)
no prose left to read — digested without a model call
  0 chat request(s); tokens 0 in / 0 out / 0 embed
applied: wrote 1139 nodes, 2739 edges
```

请重读第三行：**当时没有设置任何 API key，也没有发出任何请求。** 语法树不需要推断
`parse()` 调用了 `lex()`——它本就知道；因此把文件当作散文交给模型，是在花费 token
去换取一个比手上已有答案更差的结果。凡是解析器确知之处，模型都不会被问及。

每个处理器都带来自己的一套词汇，由处理器本身固定，而不是逐份文档临时发明——这正是事
后无需再作调和的原因，也是**某个处理器所产出的标签与属性由该处理器自行记录**、而不
记录在此处的原因。请查阅你正在使用的那一个；`drsg digest --handler <name>` 即指定了
它的名字。

每一条事实都带有 `_generated_by`，其中记有处理器的名字与版本，因此解析所得的事实与
模型的猜测始终可以区分。当两者认领同一个 key 时，**以解析器为准**，模型给出的那一份
被丢弃并计数。

上例指向的是 `src/` 而非 crate 根目录，这正是「不调用模型」与「调用模型」之间的分
界：crate 根目录下有 `Cargo.toml`，通常还有 README，而它们确实是需要阅读的散文。当
指向某个 `src/` 目录时，crate 仍会以其上层目录命名，因此导入同一 plane 的两个 crate
依然是两个 crate。

真实的代码库不止一种语言，所以整棵树是逐文件路由的：Rust 被解析，Markdown 与配置文
件成为交给模型的散文，无法读取的文件则被跳过并**计数**。解析器无法确定的部分会被报
告出来，而不是被悄悄略去——调用另一个 crate 的函数不构成边，而一个同时匹配两个函数
的名字会被留白，而不是靠猜：

```
note: 553 call(s) named nothing defined here — calls into other crates and
      the standard library are not edges
```

`--handler rust` 强制指定处理器，而不按扩展名路由。插件自身的设置位于 `drsg.toml`
的 `[plugins.<name>]` 节，原样透传——`[plugins.rust] include_source = true` 会把每个
函数自身的源码存到它的节点上以供取回，默认关闭，因为那几乎等于把整个代码库复制进
图里。

遍历会遵守 `.gitignore` 与 `.dockerignore`（一个项目对「什么是衍生物、什么是源码」
的自我声明，胜过本工具所能猜测的任何清单），并且总是跳过 `target/`、`node_modules/`
之类的目录。对未改动的树运行两次，得到的图逐字节相同。

这一能力被刻意限定为**仅限本地**——你自己机器上的 `drsg` 与 stdio MCP 服务器，而绝不
包括共享的 `drsg serve`。使解析值得其代价的，是处理器能够拉取它所拿到的那个文件**周
围**的文件；而共享服务器唯一能提供的文件系统，是它自己的那一个。

## 提供方与密钥

LLM 相关功能——语义检索的嵌入、`ask` 与导入——都会调用一个外部提供方。已内置
**OpenAI**、**DeepSeek**、**Qwen** 与 **Ollama** 的预设；任何其它端点均可用 base URL
指定。对话提供方与嵌入提供方是各自独立选择的——当某个提供方只提供其一而非其二时，
这一点尤为重要（例如 DeepSeek 仅提供对话——可与 Qwen 搭配以获取嵌入）。

**密钥从服务端环境读取，绝不从请求中读取。** 每个提供方读取其惯用的密钥变量
（`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`……）；这些也可以通过配置
文件的 `[llm]` 节提供（见[第 2 章](./getting-started.md#配置文件)）。

## 面向智能体的原语

另有两项能力（在别处记述）补全了面向智能体的接口，并与上述能力相互组合：

- **时间旅行** —— 按提交序号或时间戳读取任意历史状态，以审计或复现较早的结果。
  见[第 4 章](./query-language.md)。
- **变更流** —— 订阅一个平面，在变更提交时即时收到它，使智能体得以对图作出反应，
  而非轮询它。见[第 6 章](./sdk.md)。
