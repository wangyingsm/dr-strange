# 架构

本章阐述其内部架构。Dr Strange 以清晰的分层构建，每一层与下一层之间仅有一道狭窄的
接缝，因此引擎既可嵌入、可对外服务，也可以在存储层被替换，而不影响上层。

## 分层

| 层 | 职责 |
|---|---|
| **存储** | 具备 MVCC 快照的持久键/值，置于一个后端 trait 之后 |
| **缓存** | 解码对象的记忆化，以提交序号打版本戳 |
| **计算** | 计划执行、图算法、混合检索融合 |
| **API** | `Database` / `PlaneHandle` 接口：查询、写入、索引、时间旅行、变更流、快照 |
| **平面** | 为一切数据划定范围的贯穿性命名空间 |

在核心之上，是各个包装层：JSON-RPC Web 后端与仪表盘、各语言 SDK、命令行、MCP 服务，
以及为自然语言查询与导入提供动力的 LLM 层。

## 提交序号

有一个原语贯穿每一层：**提交序号（commit sequence）**——一个赋予每次已提交写入的
单调递增编号。它是存储引擎的 MVCC 版本、缓存的一致性戳、索引伴生文件上的新鲜度戳、
时间旅行读取的地址，以及每个变更事件所携带的序号。一个引擎级的单一时钟，无需另设
协调机制，即令各层保持一致。

## 存储

图层是针对一个后端 trait 编写的——`begin_read` 产生一个稳定的 MVCC 快照，
`begin_write` 产生一个串行化的单写者事务——其上是一组固定的逻辑表（节点、边、正向/
反向邻接、标签与属性索引、外部键、平面元数据）。键采用大端序，因此字节序即扫描序，
每个按平面或按节点的范围都是一段连续的前缀。

默认后端是一个手写的 **LSM 引擎**：

- 一次写入被追加到**预写日志（WAL）**——一条长度前缀、带 CRC32 校验的批记录，在变更
  被发布之前先 `fsync`——并被插入一个以提交序号打戳的、版本化的内存**memtable**。
- 当 memtable 超过阈值时，它被刷写为一个不可变的、有序的 **SST** 文件（带每个 SST 的
  布隆过滤器），并轮换 WAL。
- 一次读取将 memtable 叠加在各 SST 之上（最新的 run 在前），返回第一个不高于其快照的
  版本。
- **合并压缩（compaction）** 将累积的 run 合并为一个，回收已无任何读者能观测到的版本。

由于每个版本都携带其提交序号，且 SST 不可变，读者在其整个生命周期内不持有任何锁，
而一个旧快照的数据在被合并回收之前始终可达。

## 时间旅行与保留

时间旅行几乎是从 MVCC 设计中免费得来的。`begin_read_at(seq)` 将一次读取钉在任意历史
提交序号上，而读取路径——它本就返回不高于某个快照的版本——原样即可服务之。唯一的
要求是历史版本得以在合并中存活，这由一个**保留窗口**通过为合并 GC 设定下限来保证
（默认无界；一个有界窗口以历史换磁盘）。时间戳地址通过对每次提交所记录的墙钟时间做
二分查找，解析为一次提交。只有原生后端保留旧版本，因此时间旅行是原生独有的。

## 缓存

执行器从不直接接触存储；它通过一个双层缓存读取。一个查询内的 **L1** 在单次查询的
生命周期内记忆化解码后的节点、边与邻接（绑定到其快照）。一个跨查询的 **L2**——一个
有界的、打版本戳的对象缓存——由每个查询共享：仅当条目的戳等于读者的提交序号时才
提供之，因此任何写入都会静默地令面向后续快照的旧条目失效。这条精确序号规则也令历史
读取对缓存而言是安全的：它绝不会被提供一个更新的版本。

## 计算

执行器在一串行（row）之上运行逻辑计划，每一行携带其当前节点与产生它的路径，因此一次
读取得以返回连通的子图，而非孤立的端点。图算法在平面邻接的一个索引稠密帧（frame）
之上运行，只读且作用于单一快照。混合检索独立地收集每一路信号，在信号内归一化各分数，
再以加权和融合之，其中图信号从最强的命中点播种。

## 索引

向量（HNSW）与关键词（BM25）索引是内存中的注册表，其声明记录在存储中。打开时，当
伴生文件（`.hnsw` / `.bm25`）所打的提交序号戳与数据匹配时，注册表从伴生文件加载，
否则从键/值存储重建——后者始终是权威来源。一致性在提交时得以维护：一个写事务缓冲
它所隐含的索引变更，并在数据持久化之后于一把写锁下将其应用到注册表。快照将活动的
注册表序列化为伴生文件字节，而一次保 id 的恢复无需重建即可重新加载它们。

## 变更流

一个 `Database` 接受一个提交时刻的观察者。一个写事务缓冲它所做的节点与边变更；在
提交时，一旦数据持久化，这些变更被按实体折叠、在已提交的快照上解析为记录（剥去嵌入
与内部属性），并交给观察者。Web 层注册一个观察者，将每个变更集发布进一个广播通道，
由每个 `plane.watch` WebSocket 订阅者各自抽取——投递是尽力而为的，因此落后的消费者
丢弃溢出部分，而不会拖住写入方。

## 后端

存储后端是一个编译期选择：原生 LSM 引擎（默认）、遗留的 redb 引擎，或一个用于测试的
内存引擎。那些依赖旧版本的能力——时间旅行及其保留——仅存在于原生后端，并据此以特性
开关加以门控；而读取接缝无论在哪个后端都能编译。

## 线协议契约

各包装层讲 **JSON-RPC 2.0**。`drsg serve` 后端、MCP 服务与各 SDK 都使用它，而其接口
由一份作为唯一权威来源的 **OpenRPC** schema 描述：SDK 由它生成，服务端从
`rpc.discover` 返回它，而一旦该 schema、分发表与生成的客户端之间发生分歧，漂移
（drift）测试便会失败。变更流订阅是同一协议的一个 WebSocket 扩展。
