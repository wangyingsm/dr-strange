# 架构

本章阐述其内部架构。Dr Strange 以清晰的分层构建，每一层与下一层之间仅有一道狭窄的
接缝，因此引擎既可嵌入、可对外服务，也可以在存储层被替换，而不影响上层。

## 分层

- **存储（Storage）** —— 一个手写的 LSM 引擎（预写日志 + 版本化 memtable + 有序的
  SST 文件，配有每个 SST 的布隆过滤器和一个共享的块缓存），置于一个后端 trait 之后。
  它提供 MVCC：每次提交都得到一个单调递增的序号，一次读取则钉住一个稳定的快照。
  正是这一点，让时间旅行、一致快照与缓存一致性都变得廉价。
- **缓存（Cache）** —— 一个查询内与跨查询的解码对象缓存，以提交序号打版本戳，于是
  热点读取免于重复解码，而一次写入会粗粒度地令后续快照失效。
- **计算（Computation）** —— 逻辑计划之上的查询执行器，外加图算法与混合检索的融合。
- **API** —— 公开的 `Database` / `PlaneHandle` 接口：查询构造器、写入、索引、
  时间旅行、变更流，以及快照/恢复。
- **平面（Planes）** —— 贯穿全局、为一切划定范围的数据模型。

在核心之上，是各个包装层：JSON-RPC Web 后端 + 仪表盘、各语言 SDK（由 OpenRPC 生成）、
命令行、MCP 服务，以及为自然语言查询与导入提供动力的 LLM 层。
